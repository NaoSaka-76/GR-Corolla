# GR Corolla Watch

GR Corollaに関する情報を1か所に集約するモニタリングダッシュボード。GitHub Actionsで
30分おきに自動的にデータを収集し、GitHub Pagesで公開する。

GitHub Pagesは静的サイトのみでサーバー側処理ができないため、アクセスの都度リアルタイムに
取得することはできない(Google News/YouTube/TC America等はCORS制限でブラウザから直接
取得できず、アクセスごとに実スクレイピングを走らせるとレート制限で機能停止するリスクが
高い)。そのため「アクセスの都度更新」の実質的な代替として、自動更新の頻度を上げる方式を
採用している。

**公開ページ:** Settings > Pages で有効化後、`https://<owner>.github.io/GR-Corolla/`

「人気(バズっている)動画」以外の全セクションは公開日時の新しい順に並び替えている
(YouTubeの人気/新着動画のみ、性質上それぞれ再生数順/投稿日時順を維持)。

見出し文が日本語を含まない(=英語などの)場合は、見出しの下に機械翻訳した日本語訳を
小さめの文字で併記している。Google翻訳の無料エンドポイントはGitHub Actionsの共有IPからだと
レート制限(HTTP 429)で確実にブロックされるため、サーバー側(30分毎の自動収集)ではなく
各閲覧者のブラウザから直接呼び出す方式にしている(ページ表示自体は英語見出しのまま即座に行い、
日本語訳は表示後にバックグラウンドで後追い挿入される)。翻訳結果はブラウザのlocalStorageに
キャッシュされ、再訪問時は再翻訳しない。1ページに見出しが数百件あるため、翻訳エンドポイント側の
レート制限(HTTP 429)に閲覧者のIPでも達することがあり、検知した時点でそのページ表示分の翻訳は
打ち切る(無駄打ちを避けるためで、ページを再読み込みすれば改めて試みる)。エンドポイントの
仕様変更や閲覧者側のネットワーク事情によっては翻訳できない場合があり、その場合は原文の見出しの
みを表示する(記事本文までは翻訳していない)。

各記事の右上にはリンクをコピーするボタンを設置しており、クリックするとその記事のURLを
クリップボードにコピーできる(コピー後は一時的にチェックマーク表示に切り替わる)。
FR Sports Car Watch・GR86 Watch・Supra GT4 Watchの各ダッシュボードとも同じ仕様。

ページ最上部には「直近24時間ダイジェスト」パネルを表示し、各セクションで過去24時間以内に
更新された件数をボタン形式で一覧できる(クリックすると該当セクションへスクロール)。また、
過去24時間以内に公開された個別の記事・動画には「24時間以内」バッジと背景ハイライトを付与し、
一覧内でも新着情報が一目で分かるようにしている。

トヨタ公式発表以外の全セクションには、見出し文からの簡易センチメント判定(ポジティブ/ネガティブ)を
付与している(英語: VADER、日本語: 自動車レビュー向け手作り極性辞書)。ダッシュボード上では
各記事の左端の色帯とバッジで一目で判別でき、バッジにマウスオーバー(タッチ操作の場合はタップ)
すると判定根拠となった単語がツールチップで表示される。あくまで見出し文のみに基づく自動推定であり、
参考値として利用すること。

ニュース記事本文やYouTube動画の内容そのものを無料で安定的に取得する手段がないため
(Google News RSSのsummaryは見出しの複製のみ、YouTube検索結果のdescriptionSnippetも
ほとんどのケースで空)、実質的な入力は見出し文のみ。そのため、見出し中の1語だけで
結論が引っ張られないよう、英語(VADER・汎用辞書で多義語を含む)は判定根拠の単語が2つ
以上見つかった場合のみポジティブ/ネガティブを確定し、1語以下は中立として扱う
(例: "DRAG RACE"の"drag"のような自動車文脈と無関係な語の誤判定を抑制)。日本語辞書は
本ダッシュボード向けに自動車文脈のみを想定して手作りしており多義語が混ざりにくいため、
1語の一致でも判定を確定する。

## 既知の制約

- **30分おきはGitHub Actionsのcronによる近似値**: GitHub Actions側の負荷状況により実行が
  数分遅れることがある(GitHub公式のドキュメントでも明記されている既知の挙動)。また、
  TC America/スーパー耐久の公式サイトへは1回の実行で十数件のページを取得するため、
  更新頻度を30分よりさらに上げる場合は先方サイトへの負荷にも配慮すること。
- **公式API未使用**: YouTube Data API・X API・Facebook Graph API のキーは未設定。すべて
  無料の公開エンドポイント(Google News RSS、YouTube検索ページ)をベストエフォートで
  利用しているため、件数の正確性・網羅性は公式APIに劣る。
- **検索クエリはGR Corolla / GRMN Corollaの両方を明示的にカバー**: "GRMN Corolla"は
  "GR Corolla"の完全一致検索に含まれないため(別グレード名のため)、トヨタリリース・
  メディア評価・SNS話題・クレーム関連の全セクションで両方のクエリを個別に実行している。
  新グレード等が追加された場合は `scripts/sources/` 各モジュールの `QUERIES` /
  `NEWS_QUERIES` にクエリを追加することで拾えるようになる。
- **X/Facebookの投稿本体は含まれない**: 現状、投稿そのものを合法的・安定的に無料取得する
  手段がないため、ニュース/ブログでの言及を代替指標として表示している。
- **クレーム情報は社内システム未連携**: 社内CRM等とは接続しておらず、公開されている
  報道・SNS言及のみを集約した簡易モニタリング。
- **YouTube検索スクレイピングの脆弱性**: YouTube側のページ構造変更により取得に失敗する
  可能性がある。失敗時はダッシュボード上に取得エラーとして表示される。
- **見出しの日本語訳は機械翻訳のベストエフォート**: Google翻訳の非公式エンドポイントを
  APIキーなしで、各閲覧者のブラウザから直接利用している(サーバー側からの一括翻訳は
  GitHub Actionsの共有IPがレート制限されるため断念)。仕様変更や閲覧環境により翻訳できない
  場合があり、その場合は日本語訳を省略し原文の見出しのみ表示する(記事本文までは翻訳していない)。
- **グラフィカルなフルシリーズランキングはTC Americaのみ**: TC Americaは公式サイト
  (tcamerica.us)の順位表HTMLが安定して取得できるため、ドライバーズランキングを実データで
  グラフ表示している。ARAは公式サイトに全ポイント付きの順位表がなく、外部の非公式サイトが
  JavaScriptで描画する非公開フォーマットに依存しているため、フル順位表のグラフ化は
  非対応。ただしARA公式サイトのchampionship-standingsページにはNational Driver/
  Co-Driverそれぞれの上位3名(表彰台)を写真付きで紹介する静的な区画が実在するため、
  この上位3名分のみ実データで表示している(GR Corollaで参戦するドライバーには目印を付与)。
  スーパー耐久は、水素エンジンGRカローラが参戦するST-Qクラスが開発車両専用クラスで
  ポイントランキングの対象外のため非対応(いずれも「公式ランキングを検索」リンクから
  フル順位表を確認可能)。
- **レース日程はTC America・スーパー耐久・ARAとも公式サイトから一覧表示**: ARAの公式
  日程ページはページビルダー(Wix)で描画されHTML構造がイベントごとに微妙に揺れるが、
  日付パターンを軸にブロックを分類・結合する方式で概ね安定して抽出できることを確認し
  対応した(1件のみ元HTMLが破損しており抽出不可)。
- **イベント情報の正確な日程・開催地は本文まで解析できていない**: Google News RSSは
  見出し文のみで、リンク先はJavaScriptによるリダイレクトが必要なため記事本文を取得できない。
  参加を検討する場合は必ず元記事で日程・開催地を確認すること。
- **センチメント判定は見出し文のみの自動推定**: 記事本文・動画本編・コメント欄までは
  解析していない(無料で安定的に取得する手段がないため)。判定根拠語が1つ以下の場合は
  中立とする2語ゲートにより、単語1つで結論が引っ張られる誤判定を抑えているが、
  その分「弱い根拠1語のみ」のケースは中立寄りになりやすい(例: リコール関連でも
  該当語が1つしか見出しに含まれない場合は中立表示になることがある)。

より高精度な情報が必要な場合は、各社の公式APIキー(YouTube Data API v3, X API,
Facebook Graph API)を取得し、`scripts/sources/` 配下の該当モジュールを差し替えることで
精度を向上できる。

- **お客様の声・クレームの「話題順」は簡易的な代替指標**: 実際のSNS拡散数やエンゲージメント数
  ではなく、Google News検索結果内での上位表示度(検索順位)を注目度の代替指標として使用している。
- **YouTube動画の概要欄プレビューは未実装**: 動画ごとに概要欄を追加取得する方式を試したが、
  GitHub Actionsの共有IPから動画詳細ページへ連続アクセスするとGoogle側のボット対策
  (HTTP 429)にほぼ確実に引っかかり、実用的な取得率を確保できなかったため見送っている。
  検索結果ページからのタイトル・サムネイル・再生数の取得は同じ環境で問題なく動作する。

## 構成

```
scripts/
  fetch_data.py        # 全ソースを集約し site/data/latest.json を生成
  sources/
    common.py           # RSS取得・数値/日時パース等の共通処理
    sentiment.py         # 見出し文からのポジティブ/ネガティブ推定(VADER + 日本語辞書、判定根拠語も返す)
    toyota_news.py
    motorsports.py       # TC America / ARA / スーパー耐久
    standings.py          # TC America公式サイトの実データランキング取得
    schedule.py           # TC America / スーパー耐久の年間レース日程取得
    events.py              # 世界各地のGR Corollaイベント情報
    youtube.py
    social_buzz.py
    media_reviews.py
    complaints.py
site/
  index.html / style.css / app.js   # ダッシュボード本体(静的サイト)
  data/latest.json                  # 自動生成される最新データ(コミット対象外)
  data/nurburgring.json             # ニュルブルクリンクラップタイムの手動更新データ(コミット対象)
.github/workflows/update-dashboard.yml  # 30分おきの自動更新 + GitHub Pagesデプロイ
```

## ローカルでの動作確認

```bash
cd scripts
pip install -r requirements.txt
python fetch_data.py          # site/data/latest.json を生成
cd ../site
python3 -m http.server 8000   # http://localhost:8000 で確認
```

## GitHub Pagesの有効化(初回のみ)

リポジトリの Settings > Pages > Build and deployment > Source を
**GitHub Actions** に設定する。設定後、`update-dashboard` ワークフローの実行(スケジュール
または手動の workflow_dispatch)によって自動的に公開される。
